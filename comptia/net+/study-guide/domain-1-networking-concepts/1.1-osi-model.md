# Objective 1.1 — Explain concepts related to the Open Systems Interconnection (OSI) reference model

The OSI (Open Systems Interconnection) reference model is the single most important mental framework on the Network+ exam. It is a seven-layer conceptual model, standardized by the ISO, that describes how data moves from an application on one host, down through the network stack, across the wire, and back up the stack on the receiving host. The exam tests it two ways: **directly** ("At which OSI layer does a switch operate?") and **indirectly** — nearly every troubleshooting scenario expects you to isolate a problem to a layer ("users can ping by IP but not by name" is a Layer 7 DNS issue, not a Layer 1 cable issue). If you can instantly map any device, protocol, address type, or symptom to its layer, you will pick up easy points across all five exam domains.

**Mnemonics** (know one for each direction):

| Direction | Mnemonic | Layers |
|---|---|---|
| Layer 1 → 7 (bottom-up) | **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way | Physical, Data link, Network, Transport, Session, Presentation, Application |
| Layer 7 → 1 (top-down) | **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing | Application, Presentation, Session, Transport, Network, Data link, Physical |

> 💡 **Exam Tip:** Memorize the layer **numbers**, not just the names. Exam questions frequently say "a Layer 3 device" or "a Layer 4 protocol" without naming the layer. Layer 1 = Physical ... Layer 7 = Application.

## The Big Picture: One Table to Rule Them All

| # | Layer | PDU | Addressing | Key Devices | Key Protocols / Technologies |
|---|-------|-----|------------|-------------|------------------------------|
| 7 | Application | Data | — | Application gateways, L7 firewalls/proxies | HTTP/HTTPS, FTP, SMTP, DNS, DHCP, SNMP, Telnet, SSH, SIP |
| 6 | Presentation | Data | — | — | TLS/SSL encryption, JPEG/GIF/PNG, ASCII/Unicode, compression |
| 5 | Session | Data | — | — | NetBIOS, RPC, PPTP session setup, SIP session control |
| 4 | Transport | Segment (TCP) / Datagram (UDP) | Port numbers | Load balancers (L4), stateful firewalls | TCP, UDP |
| 3 | Network | Packet | IP addresses (logical) | Routers, Layer 3 switches, firewalls | IP, ICMP, IPSec, routing protocols (OSPF, BGP, EIGRP), IGMP |
| 2 | Data link | Frame | MAC addresses (physical) | Switches, bridges, NICs, wireless APs | Ethernet (802.3), Wi-Fi (802.11), ARP*, PPP, STP, VLANs/802.1Q |
| 1 | Physical | Bits | — | Hubs, repeaters, media converters, transceivers, cables, connectors | Ethernet physical standards, DSL, SONET, Bluetooth/Wi-Fi radio |

\* ARP is usually described as operating at Layer 2 (or "between Layer 2 and Layer 3") because it resolves Layer 3 IP addresses into Layer 2 MAC addresses.

> 💡 **Exam Tip:** PDU (Protocol Data Unit) names are heavily tested: **bits** (L1), **frames** (L2), **packets** (L3), **segments** (L4, TCP) / **datagrams** (L4, UDP), and generically **data** (L5–L7). Mnemonic bottom-up: "**B**its **F**or **P**acket **S**witching **D**elivery."

## Layer 1 - Physical

### What it is
The Physical layer transmits and receives raw **bits** (1s and 0s) over a physical medium. It defines everything tangible and electrical/optical/radio: voltages, light pulses, radio frequencies, modulation, bit timing/synchronization, connector shapes, pinouts, and cable specifications.

### What lives here
- **Media:** copper twisted pair (Cat 5e/6/6a/7/8), coaxial, fiber optic (single-mode/multimode), radio waves (Wi-Fi, cellular, satellite frequencies).
- **Devices:** hubs, repeaters, media converters, modems, transceivers (SFP/QSFP), patch panels, couplers.
- **Concepts:** bandwidth of the physical link, signaling, attenuation, interference/EMI, crosstalk.

### Why it matters / exam framing
Layer 1 problems are the most common real-world failures: bad cables, wrong cable category, transposed TX/RX, failed transceivers, unplugged ports. In the troubleshooting methodology, "bottom-to-top" starts here. If there is **no link light**, think Layer 1 before anything else.

> ⚠️ **Common Pitfall:** A **hub** is Layer 1, a **switch** is Layer 2. Hubs blindly repeat bits out every port (one collision domain); switches make forwarding decisions based on MAC addresses. If a question says a device "regenerates a signal" or "repeats to all ports," it is Layer 1.

## Layer 2 - Data link

### What it is
The Data link layer packages bits into **frames** and handles node-to-node delivery **on the same local network segment**. It provides physical addressing via **MAC addresses** (48-bit hardware addresses burned into NICs, written like `AA:BB:CC:11:22:33`) and performs error detection with the **FCS/CRC** (Frame Check Sequence) trailer.

### Sublayers
- **LLC (Logical Link Control, 802.2):** the upper sublayer; identifies which Layer 3 protocol the frame carries and provides flow-control hooks.
- **MAC (Media Access Control):** the lower sublayer; handles physical addressing and media access — how devices share the wire (e.g., CSMA/CD historically on Ethernet, CSMA/CA on Wi-Fi).

### What lives here
- **Devices:** switches, bridges, NICs, wireless access points.
- **Protocols/tech:** Ethernet (802.3), Wi-Fi (802.11), ARP, PPP, VLANs and 802.1Q tagging, STP (Spanning Tree Protocol), LACP link aggregation.
- **Frame structure:** destination MAC, source MAC, type/length, payload, FCS trailer. Layer 2 is the only layer that adds a **trailer**.

### Why it matters / exam framing
Switches learn MAC addresses from source addresses of incoming frames and build a **MAC address table** (CAM table) to forward frames only out the correct port. Each switch port is its own collision domain. MAC flooding, ARP poisoning, VLAN hopping (Domain 4) are all Layer 2 attacks.

> 💡 **Exam Tip:** The first half (24 bits) of a MAC address is the **OUI** (Organizationally Unique Identifier) identifying the manufacturer; the last 24 bits are the device-specific portion. The broadcast MAC address is `FF:FF:FF:FF:FF:FF`.

## Layer 3 - Network

### What it is
The Network layer moves **packets** between different networks using **logical addressing (IP addresses)** and **routing**. Where Layer 2 delivers within a LAN, Layer 3 handles end-to-end delivery across internetworks — choosing the best path hop by hop.

### What lives here
- **Devices:** routers, Layer 3 (multilayer) switches, firewalls (packet filtering).
- **Protocols:** IPv4, IPv6, ICMP (ping/traceroute), IPSec, IGMP, and routing protocols (OSPF, EIGRP, BGP, RIP).
- **Concepts:** IP addressing and subnetting, routing tables, TTL (Time to Live) decrementing at each hop, fragmentation, broadcast domain boundaries.

### Why it matters / exam framing
Routers separate **broadcast domains** — broadcasts do not cross a router. Scenario cues that point to Layer 3: "cannot reach hosts on a different subnet," "incorrect default gateway," "TTL expired," "destination unreachable."

> ⚠️ **Common Pitfall:** Both switches and routers can "forward traffic," but the addressing decides the layer: forwarding by **MAC address = Layer 2**; forwarding/routing by **IP address = Layer 3**. A "Layer 3 switch" routes between VLANs, so it operates at both layers.

## Layer 4 - Transport

### What it is
The Transport layer provides end-to-end (host-to-host) delivery of **segments** (TCP) or **datagrams** (UDP) between applications, identified by **port numbers**. It decides *how* data is delivered: reliably with connection setup, sequencing, acknowledgment, and retransmission (TCP), or fast and connectionless with no guarantees (UDP).

### Key functions
- **Segmentation and reassembly:** breaking application data into segments and rebuilding it in order.
- **Connection management:** TCP three-way handshake (SYN → SYN-ACK → ACK) and graceful teardown (FIN/ACK).
- **Reliability:** sequence numbers, acknowledgments, retransmission of lost segments.
- **Flow control:** TCP sliding **windowing** — the receiver advertises how much data it can accept, throttling the sender.
- **Multiplexing:** port numbers (0–65535) let one host run many conversations at once. Well-known ports are 0–1023.

### What lives here
- **Protocols:** TCP, UDP.
- **Devices:** load balancers (L4 mode), stateful firewalls that track TCP sessions by port/state.

> 💡 **Exam Tip:** If a question mentions **port numbers, TCP, UDP, handshakes, windowing, or acknowledgments**, the answer is Layer 4. See Objective 1.4 for the full TCP vs. UDP deep-dive.

## Layer 5 - Session

### What it is
The Session layer establishes, manages (maintains), and terminates **sessions** — the ongoing dialogs between applications on two hosts. It handles dialog control (half-duplex/full-duplex turn-taking), checkpointing, and session recovery/resumption.

### What lives here
- **Protocols/examples:** NetBIOS, RPC (Remote Procedure Call), SIP session management for VoIP calls, sockets/session tokens conceptually, PAP/CHAP authentication dialogs are often placed here.

### Why it matters / exam framing
Layer 5 rarely maps to a physical device — it's about the *conversation*. Exam cues: "establishing, maintaining, and tearing down a connection between applications," "session timeout," "resuming an interrupted transfer at a checkpoint."

> ⚠️ **Common Pitfall:** Do not confuse a Layer 5 **session** with a Layer 4 **connection**. TCP builds the transport connection (the pipe); the Session layer manages the application dialog running through that pipe. VoIP is the classic example: SIP sets up/tears down the call session (L5), while the voice itself rides RTP over UDP (L4 and below).

## Layer 6 - Presentation

### What it is
The Presentation layer is the network's **translator**. It ensures data sent by the application layer of one system is readable by the application layer of another. Its three jobs are: **translation/formatting**, **encryption/decryption**, and **compression/decompression**.

### What lives here
- **Character encoding:** ASCII, Unicode/UTF-8, EBCDIC.
- **File/data formats:** JPEG, GIF, PNG, MPEG, MP4.
- **Encryption:** TLS/SSL is most commonly associated with Layer 6 on the exam (it "presents" encrypted data), though real-world TLS spans layers.
- **Compression:** reducing data size before transmission.

### Why it matters / exam framing
Exam cues: any mention of **encryption, data formats, character sets, or compression** → Layer 6. "A user receives a file but the characters are garbled" (encoding mismatch) is a Presentation-layer framing.

> 💡 **Exam Tip:** Remember the three E's/F's of Layer 6: **E**ncryption, **F**ormatting (translation), and compression. On CompTIA exams, **TLS/SSL = Layer 6** unless the question is specifically about the HTTPS application protocol.

## Layer 7 - Application

### What it is
The Application layer is the interface between the network stack and the **network-aware services** users consume. It does NOT mean "the application itself" (Chrome, Outlook) — it means the protocols those applications use: HTTP for the browser, SMTP for the mail client, DNS for name lookups.

### What lives here
- **Protocols:** HTTP/HTTPS, FTP/SFTP/TFTP, SMTP/SMTPS, POP3/IMAP, DNS, DHCP, SNMP, Telnet, SSH, LDAP/LDAPS, NTP, SIP, RDP, SMB.
- **Devices/services:** Layer 7 (next-generation) firewalls, application-aware load balancers, proxies, IDS/IPS with deep packet inspection.

### Why it matters / exam framing
Most of the port/protocol memorization in Objective 1.4 lives at Layer 7. Troubleshooting cue: connectivity works (ping succeeds) but a *service* fails (web page won't load, name resolution fails) → Layer 7.

> ⚠️ **Common Pitfall:** "The user's application is slow, so it's a Layer 7 problem" — not necessarily! Slow applications are often caused by lower-layer issues (congestion at L1–L3, retransmissions at L4). Match the *symptom mechanism* to the layer, not the user's perception.

## Encapsulation and De-encapsulation

**Encapsulation** is the process of wrapping data with protocol headers as it moves **down** the stack on the sending host. Each layer adds its own header (and Layer 2 also adds a trailer):

1. **Layers 7–5:** user data is produced and formatted → **data**.
2. **Layer 4:** a TCP or UDP header (source/destination **ports**, sequence numbers) is added → **segment/datagram**.
3. **Layer 3:** an IP header (source/destination **IP addresses**, TTL) is added → **packet**.
4. **Layer 2:** a frame header (source/destination **MAC addresses**) and FCS trailer are added → **frame**.
5. **Layer 1:** the frame is converted to **bits** and transmitted on the medium.

**De-encapsulation** is the exact reverse on the receiving host: bits → frame (check FCS, strip L2 header) → packet (check IP, strip L3 header) → segment (deliver to correct port, strip L4 header) → data to the application.

```
 Sender (encapsulation)                    Receiver (de-encapsulation)
 L7  [        DATA        ]                [        DATA        ]  L7
 L4  [TCP hdr|   DATA     ]                [TCP hdr|   DATA     ]  L4
 L3  [IP hdr|TCP hdr|DATA ]                [IP hdr|TCP hdr|DATA ]  L3
 L2  [Eth|IP|TCP|DATA|FCS ]                [Eth|IP|TCP|DATA|FCS ]  L2
 L1  1011010010110... ────────── media ──────────► 1011010010110  L1
```

> 💡 **Exam Tip:** Know the header order on the wire from outside-in: **Ethernet header → IP header → TCP/UDP header → data → FCS trailer**. A packet-capture question showing this structure is testing encapsulation. Also remember: routers strip and rebuild the **Layer 2 frame** at every hop, but the **Layer 3 packet** (source/destination IPs) stays the same end to end (barring NAT).

## Addressing at Each Layer

| Layer | Address type | Example | Scope |
|---|---|---|---|
| 2 - Data link | MAC address (48-bit, hexadecimal) | `00:1A:2B:3C:4D:5E` | Local segment only; changes at every router hop |
| 3 - Network | IP address (IPv4 32-bit / IPv6 128-bit) | `192.168.1.10` / `2001:db8::1` | End-to-end, logical, hierarchical |
| 4 - Transport | Port number (16-bit, 0–65535) | `443` | Identifies the application/service on a host |

A full conversation endpoint is a **socket**: IP address + port (e.g., `192.168.1.10:443`).

## Common Exam Traps and Edge Cases

A handful of items sit "between" layers or are frequently mis-assigned. Here is how the exam expects you to classify them:

| Item | Exam-expected layer | Why it's tricky |
|---|---|---|
| **ARP** | Layer 2 (or "between 2 and 3") | It resolves an L3 IP into an L2 MAC; it is carried directly in frames, so CompTIA treats it as Data link. |
| **TLS/SSL** | Layer 6 | Encryption = Presentation on the exam, even though TLS actually rides above TCP in real stacks. |
| **NIC** | Layer 2 (with L1 aspects) | The card contains the MAC address (L2) but also does physical signaling (L1). "MAC address" in the question → L2. |
| **Access point** | Layer 2 | It bridges 802.11 frames to 802.3 frames — a wireless bridge. |
| **Load balancer** | Layer 4 or 7 | By IP/port = L4; by URL/cookie/HTTP header content = L7. Read the question's decision criteria. |
| **Firewall** | Layer 3/4, or 7 for NGFW | Packet filter = 3/4; application-aware/deep packet inspection = 7. |
| **Multilayer (L3) switch** | Layers 2 **and** 3 | Switches frames within VLANs, routes packets between VLANs. |
| **ICMP** | Layer 3 | It has no ports and rides directly in IP — it is not a transport protocol. |
| **DNS, DHCP** | Layer 7 | They *use* UDP (L4) but *are* Application-layer services. |
| **Session vs. connection** | L5 vs. L4 | TCP builds the connection (L4); the Session layer manages the application dialog (L5). |

> ⚠️ **Common Pitfall:** "Which layer does X *use*?" vs. "Which layer *is* X?" DNS **uses** Layer 4 (UDP 53) but **is** a Layer 7 service. The exam almost always asks what the protocol/service *is*.

## Collision Domains vs. Broadcast Domains by Device

Layer placement determines how devices carve up the network:

| Device | Collision domains created | Broadcast domains created |
|---|---|---|
| Hub / repeater (L1) | 1 (all ports share it) | 1 (all ports share it) |
| Switch (L2) | 1 **per port** | 1 per **VLAN** |
| Router (L3) | 1 per interface | 1 **per interface** — broadcasts stop here |

Example: two 8-port switches connected through a router = 16 collision domains (one per switch port in use) and 2 broadcast domains (one per router interface).

## OSI vs. TCP/IP Model Mapping

The TCP/IP (DoD) model is the practical four-layer model the Internet actually uses. The exam expects you to map between the two:

| OSI layer(s) | TCP/IP layer | PDU | Example protocols |
|---|---|---|---|
| 7 Application, 6 Presentation, 5 Session | **Application** | Data | HTTP, DNS, SMTP, TLS |
| 4 Transport | **Transport** | Segment/Datagram | TCP, UDP |
| 3 Network | **Internet** | Packet | IP, ICMP, IPSec |
| 2 Data link, 1 Physical | **Network Access** (Link) | Frame/Bits | Ethernet, Wi-Fi |

> 💡 **Exam Tip:** The top three OSI layers collapse into TCP/IP's single **Application** layer, and the bottom two collapse into **Network Access**. If asked which TCP/IP layer TLS or NetBIOS belongs to, the answer is Application.

## Key Takeaways

- [ ] I can recite the 7 layers by name **and number** in both directions (PDNTSPA / APSTNDP mnemonics).
- [ ] I know the PDU per layer: bits (1), frames (2), packets (3), segments/datagrams (4), data (5–7).
- [ ] I can place devices: hub/repeater/cable/transceiver = L1; switch/bridge/AP/NIC = L2; router/L3 switch = L3; load balancer/stateful firewall = L4; NGFW/proxy = up to L7.
- [ ] I can place addressing: MAC = L2, IP = L3, port = L4 (IP + port = socket).
- [ ] I can place protocols: Ethernet/ARP/STP = L2; IP/ICMP/IPSec/routing protocols = L3; TCP/UDP = L4; NetBIOS/RPC = L5; TLS/formats/encoding = L6; HTTP/DNS/SMTP/etc. = L7.
- [ ] I can explain encapsulation (headers added going down) and de-encapsulation (headers stripped going up), and that L2 adds the only trailer (FCS).
- [ ] I know routers rewrite the L2 frame each hop while the L3 packet addressing persists end to end, and that routers bound broadcast domains while switch ports bound collision domains.
- [ ] I can map OSI ↔ TCP/IP: 7+6+5 → Application, 4 → Transport, 3 → Internet, 2+1 → Network Access.

## Self-Check Questions

1. A technician captures traffic and sees a unit of data containing a source MAC address, a destination MAC address, and an FCS trailer. What is this PDU called, and at which OSI layer was it created?
2. Users on VLAN 10 cannot reach a server on VLAN 20, but can reach every host in their own VLAN. Which OSI layer is most likely involved, and what device performs the needed function?
3. During a file download, the receiving host advertises a smaller buffer size, and the sender slows its transmission rate. What is this mechanism called and at which layer does it occur?
4. Which OSI layer is responsible for data encryption, compression, and translating character encodings such as ASCII to Unicode?
5. In the TCP/IP model, which single layer corresponds to OSI Layers 5, 6, and 7?

<details>
<summary>Answers</summary>

1. It is a **frame**, created at **Layer 2 (Data link)**. MAC addresses and the FCS trailer are the giveaway — Layer 2 is the only layer that adds a trailer.
2. **Layer 3 (Network)**. Traffic between VLANs must be routed; a **router or Layer 3 switch** is required because VLANs are separate broadcast domains/subnets.
3. **Flow control via TCP windowing (the sliding window)**, at **Layer 4 (Transport)**. The receiver's advertised window throttles the sender to prevent buffer overflow.
4. **Layer 6 (Presentation)** — its three core jobs are translation/formatting, encryption/decryption, and compression.
5. The **Application layer** of the TCP/IP model absorbs OSI's Application, Presentation, and Session layers.
