# Objective 1.2 — Compare and contrast networking appliances, applications, and functions

This objective is a "compare and contrast" objective, which tells you exactly how the exam will test it: you will be given a requirement or scenario and asked to pick the **right appliance or function**, or asked to distinguish two devices that superficially do similar things (router vs. Layer 3 switch, IDS vs. IPS, NAS vs. SAN, forward vs. reverse proxy). For every device below, know three things: **what layer it operates at, what problem it solves, and what distinguishes it from its closest sibling**. Also remember the overarching theme of N10-009: almost every appliance now exists in both **physical** (dedicated hardware) and **virtual** (software/VM) form.

## Physical and Virtual Appliances

Every appliance in this objective can be deployed as:

| Form | Description | Pros | Cons |
|---|---|---|---|
| **Physical appliance** | Purpose-built hardware (a rack-mounted router, firewall, load balancer) | Dedicated performance, hardware acceleration (ASICs), predictable throughput | Cost, rack space/power/cooling, slow to deploy and scale, single physical location |
| **Virtual appliance** | The same function delivered as software — a VM image or cloud service (virtual router, virtual firewall, vLB) | Rapid deployment, snapshots, easy scaling/cloning, lower capex, fits cloud/NFV designs | Shares host resources (contention), performance depends on hypervisor, licensing models |

> 💡 **Exam Tip:** A question describing "deploying a firewall in the cloud within minutes without purchasing hardware" is pointing at a **virtual appliance**. This concept links directly to **NFV** in Objective 1.3 — NFV is the framework for running network functions as software.

### Router

- **Layer:** 3 (Network).
- **What it does:** Connects **different networks** and forwards **packets** between them based on **IP addresses**, using a **routing table** built from static routes and/or dynamic routing protocols (OSPF, EIGRP, BGP).
- **Key behaviors:** Each router hop decrements the packet's **TTL**, rewrites the Layer 2 frame, and separates **broadcast domains** — broadcasts do not cross a router. Routers are the boundary between your LAN and the WAN/Internet.
- **Virtual form:** virtual routers in hypervisors and cloud route tables in a VPC.

### Switch

- **Layer:** 2 (Data link). (Multilayer/Layer 3 switches also route.)
- **What it does:** Connects devices **within** a network and forwards **frames** based on **MAC addresses**. It learns source MACs from incoming frames and stores them in the **MAC address (CAM) table**, forwarding subsequent frames only out the correct port.
- **Key behaviors:** Each switch port is its own **collision domain** (full-duplex, no collisions in modern networks); all ports in a VLAN share one **broadcast domain**. Supports VLANs, 802.1Q trunking, STP loop prevention, PoE.
- **Unknown/broadcast handling:** frames to an unknown MAC or the broadcast MAC are flooded out all ports in the VLAN except the ingress port.

#### Router vs. switch (L3 vs. L2) — the classic comparison

| | Router | Switch |
|---|---|---|
| OSI layer | 3 | 2 |
| Forwards | Packets | Frames |
| Decision based on | IP address / routing table | MAC address / CAM table |
| Domain separation | Separates broadcast domains | Separates collision domains (per port) |
| Connects | Different networks (LAN↔LAN, LAN↔WAN) | Devices within one network/VLAN |
| Typical protocols | OSPF, BGP, EIGRP, NAT | STP, VLAN/802.1Q, LACP |

> ⚠️ **Common Pitfall:** A **Layer 3 switch** blurs the line: it switches within VLANs at L2 *and* routes between VLANs at L3 (using SVIs). If the scenario is "route between VLANs at high speed inside the LAN," pick the Layer 3 switch; if it's "connect the LAN to the Internet/WAN," pick the router.

### Firewall

- **Layer:** 3/4 traditionally; up to 7 for next-generation firewalls.
- **What it does:** Enforces a security policy by permitting or denying traffic between zones (e.g., LAN, WAN, screened subnet/DMZ) based on rules (ACLs).

| Firewall type | How it works | Layer |
|---|---|---|
| **Packet-filtering (stateless)** | Evaluates each packet in isolation against rules (source/dest IP, port, protocol). No memory of prior packets — return traffic needs explicit rules. | 3–4 |
| **Stateful** | Tracks the **state of connections** in a state table (e.g., TCP handshake status). Automatically allows return traffic for established outbound sessions. The modern default. | 4 |
| **Next-generation firewall (NGFW)** | Adds **application awareness/deep packet inspection (DPI)**, user identity, integrated IPS, TLS inspection, URL/content filtering — can block "Facebook chat" while allowing "Facebook," regardless of port. | Up to 7 |

> 💡 **Exam Tip:** Scenario says the firewall "allows return traffic automatically for internally initiated sessions" → **stateful**. Scenario says it "identifies and blocks specific applications regardless of port" → **NGFW / Layer 7**.

### Intrusion detection system (IDS) / Intrusion prevention system (IPS)

Both inspect traffic for malicious activity. The difference is placement and action:

| | IDS | IPS |
|---|---|---|
| Placement | **Out-of-band / passive** — receives a *copy* of traffic (via port mirroring/SPAN or a network tap) | **Inline** — sits directly in the traffic path |
| Action on attack | **Detects and alerts/logs only** — cannot stop the packet | **Detects and actively blocks/drops** malicious traffic in real time |
| Risk | Attack may succeed before humans react | A false positive can block legitimate traffic; adds latency; is a potential point of failure |
| Failure impact | None to traffic flow | If it fails closed, it can take down the link (fail-open vs. fail-closed design matters) |

**Detection methods (apply to both):**
- **Signature-based:** matches traffic against a database of known attack patterns. Accurate for known threats, but blind to new (zero-day) attacks; requires constant signature updates.
- **Anomaly/behavior-based:** builds a baseline of "normal" and flags deviations. Can catch novel attacks, but more false positives.

- **Host vs. network variants:** HIDS/HIPS run on an individual host; NIDS/NIPS watch network segments.

> ⚠️ **Common Pitfall:** "The security team wants to be alerted to attacks without any risk of disrupting production traffic" = **IDS** (passive). "Must automatically stop the attack" = **IPS** (inline). Watch for the words *passive/copy/mirror* vs. *inline/block/prevent*.

### Load balancer

- **Layer:** 4 (by IP/port) or 7 (content/application-aware).
- **What it does:** Distributes incoming client requests across a **pool/farm of servers** to increase capacity (scalability), improve performance, and provide **high availability/fault tolerance** — if one server fails, traffic goes to the survivors. Clients connect to a single **virtual IP (VIP)**.

**Scheduling algorithms:**
- **Round-robin:** requests are handed to each server in rotation (1, 2, 3, 1, 2, 3...). Simple; assumes equal server capacity. **Weighted round-robin** biases toward more powerful servers.
- **Least connections:** the next request goes to the server currently handling the **fewest active connections** — better when session lengths vary.
- Others to recognize: source-IP hash / **session persistence ("sticky sessions")** keeps a client pinned to the same backend server (important for apps that store session state locally).

**Health checks:** the load balancer probes each backend (ping, TCP connect, or an HTTP request expecting 200 OK). Servers failing health checks are pulled from rotation automatically.

> 💡 **Exam Tip:** "Users are randomly logged out of the web app when their requests hit different servers" → enable **session persistence/sticky sessions**. "One server is overloaded while others idle during long downloads" → switch round-robin to **least connections**.

### Proxy

A proxy is an intermediary that terminates a client connection and opens its own connection to the destination — the two ends never talk directly.

| | Forward proxy | Reverse proxy |
|---|---|---|
| Sits in front of | **Clients** (internal users) | **Servers** |
| Direction | Outbound: clients → proxy → Internet | Inbound: Internet clients → proxy → internal servers |
| Purposes | Content/URL filtering, caching frequently accessed pages, hiding client identity, logging user activity, malware scanning | Hides/protects servers, TLS termination/offload, caching, compression, WAF functions, load distribution |
| Who benefits/is hidden | The client | The server |

- **Transparent proxy:** intercepts traffic without client configuration; users may not know it exists.

> ⚠️ **Common Pitfall:** Forward vs. reverse is about **who the proxy represents**. "Filter employee web browsing" = forward proxy. "Single public endpoint that shields a farm of web servers and offloads TLS" = reverse proxy (functionally overlapping with a Layer 7 load balancer).

### Network-attached storage (NAS)

- **What it is:** A dedicated storage appliance attached to the **existing LAN** that serves **file-level** storage — clients see shared folders/files.
- **Protocols:** **SMB/CIFS** (Windows), **NFS** (Unix/Linux), sometimes AFP/FTP.
- **Traits:** Inexpensive, easy to deploy, great for file shares, home directories, backups. Performance is bounded by the shared LAN. The NAS's own OS manages the file system.

### Storage area network (SAN)

- **What it is:** A **dedicated, separate high-speed network** that provides **block-level** storage — servers see raw disks (LUNs) they format with their own file systems, just like local drives.
- **Protocols:** **Fibre Channel (FC)** on dedicated FC switches/HBAs; **iSCSI** (SCSI commands over TCP/IP on standard Ethernet, TCP 3260); FCoE (FC over Ethernet).
- **Traits:** High performance and low latency for databases, virtualization datastores, email servers. Expensive and complex.

#### NAS vs. SAN

| | NAS | SAN |
|---|---|---|
| Storage level | **File-level** (folders/files) | **Block-level** (raw disks/LUNs) |
| Network | Shared existing LAN (Ethernet/TCP-IP) | Dedicated storage network |
| Protocols | SMB/CIFS, NFS | Fibre Channel, iSCSI, FCoE |
| Client sees | A network share | A local disk |
| Cost/complexity | Low | High |
| Best for | File sharing, backups, small office | Databases, VM datastores, enterprise workloads |

> 💡 **Exam Tip:** Match the protocol to the technology: **SMB/NFS → NAS (file-level)**; **Fibre Channel/iSCSI → SAN (block-level)**. "Servers need storage that appears as local disks" = SAN. "Users need a shared folder" = NAS.

### Wireless — Access point (AP)

- **Layer:** 2 (it bridges 802.11 wireless frames to 802.3 wired Ethernet).
- **What it does:** Provides Wi-Fi connectivity, advertising one or more SSIDs and connecting wireless clients to the wired LAN. Often powered via **PoE**.
- **Autonomous AP:** fully self-contained; each AP configured individually — fine for a handful of APs, unmanageable at scale.
- **Lightweight AP:** minimal local intelligence; configuration and control come from a **wireless controller** (often tunneled via CAPWAP).

### Wireless — Controller (WLC)

- **What it does:** Centrally manages fleets of lightweight APs: pushes SSIDs/security settings/firmware, dynamically tunes **channels and transmit power**, supports seamless client **roaming** between APs, detects rogue APs, and applies consistent policy.
- **Forms:** hardware appliance, VM, or cloud-managed (e.g., controller-as-a-service).

> 💡 **Exam Tip:** "A company with 200 APs across 5 sites needs centralized configuration and seamless roaming" → deploy a **wireless LAN controller** with lightweight APs. A few standalone APs in a small office → autonomous APs.

## Applications

### Content delivery network (CDN)

- **What it is:** A geographically distributed network of **edge servers** that **cache content close to users** so requests are served from a nearby node instead of the distant origin server.
- **How it works:** DNS/anycast steers each user to the nearest edge location; static content (images, video, scripts, downloads) is cached at the **edge**. Cache misses are fetched from the origin and then cached.
- **Why it matters:** Lower latency, faster page loads, reduced load and bandwidth on the origin, resilience to traffic spikes, and absorption of DDoS attacks. Examples: Cloudflare, Akamai, Amazon CloudFront.

> 💡 **Exam Tip:** Scenario cue: "users on other continents experience slow load times for video/static content" → **CDN with edge caching**. CDNs commonly rely on **anycast** addressing (Objective 1.4) to route users to the nearest node.

## Functions

### Virtual private network (VPN)

- **What it is:** An **encrypted tunnel** over an untrusted network (usually the Internet) that lets remote parties communicate as if on the same private network. Provides confidentiality (encryption), integrity, and authentication.
- **Types:**
  - **Site-to-site:** router/firewall to router/firewall — permanently connects two offices; transparent to end users.
  - **Client-to-site (remote access):** an individual user's device tunnels into the corporate network (VPN client software or clientless via browser/TLS).
  - **Split tunnel vs. full tunnel:** split sends only corporate-bound traffic through the tunnel (better performance, less oversight); full tunnels everything (more control/security, more bandwidth used).
- **Protocols:** **IPSec** (see Objective 1.4 for AH/ESP/IKE), TLS/SSL VPNs (e.g., OpenVPN, clientless portals), historically PPTP/L2TP.

### Quality of service (QoS)

- **What it is:** A set of techniques that **prioritize certain traffic** so latency-sensitive applications (voice, video, real-time control) get preferential treatment when links are congested. Without QoS, all traffic is best-effort FIFO.
- **How it works (high level):**
  1. **Classification/marking:** traffic is identified (by port, application, interface) and tagged with a priority value — **DSCP** (Differentiated Services Code Point, a 6-bit field in the IP header, Layer 3) or **CoS** (Class of Service, a 3-bit 802.1p field in the 802.1Q VLAN tag, Layer 2).
  2. **Queuing/scheduling:** routers/switches service higher-priority queues first.
  3. **Policing/shaping:** traffic exceeding limits is dropped (policing) or buffered/delayed (shaping).
- **Why it matters:** VoIP is intolerant of latency (>150 ms one-way), **jitter** (variation in delay), and packet loss. QoS ensures a large file transfer can't starve a phone call.

> ⚠️ **Common Pitfall:** **DSCP marks at Layer 3** (in the IP header, survives routing) while **CoS marks at Layer 2** (in the VLAN tag, rewritten per hop). If the question mentions the IP header or end-to-end marking, it's DSCP; if it mentions 802.1p/VLAN tags on a trunk, it's CoS.

### Time to live (TTL)

- **In IP (routing):** TTL is an **8-bit field in the IPv4 header** (max 255) set by the sender (commonly 64 or 128). **Every router hop decrements TTL by 1.** When TTL reaches 0, the router **discards the packet** and sends an **ICMP Time Exceeded (Type 11)** message back to the source. Purpose: **prevent packets from looping forever** during routing loops. In IPv6 the same field is renamed **Hop Limit**.
- **Traceroute trick:** traceroute deliberately sends packets with TTL=1, 2, 3... and maps the path from the ICMP Time Exceeded replies each router returns.
- **In DNS (caching):** a DNS record's TTL is **how long (in seconds) resolvers may cache the record** before re-querying. Low TTL = faster propagation of changes but more query load; high TTL = better performance but slower change propagation. Admins lower the TTL before planned migrations.

> 💡 **Exam Tip:** TTL appears in *two* exam contexts — **IP TTL** (hop count, loop prevention, decremented by routers, basis of traceroute) and **DNS TTL** (cache lifetime in seconds). Read the question carefully to see which one is being asked. "Changed the server's IP but users still reach the old address" = DNS TTL caching.

## VPN Deployment Variants at a Glance

| Variant | Connects | Notes |
|---|---|---|
| Site-to-site | Office network ↔ office network | Gateway devices build the tunnel; users don't run VPN software |
| Client-to-site (remote access) | One user's device ↔ corporate network | VPN client app, or **clientless** via HTTPS browser portal |
| Split tunnel | Only corporate traffic tunneled | Better performance; Internet traffic bypasses inspection |
| Full tunnel | All traffic tunneled | Maximum control/visibility; more bandwidth and latency |

## Key Takeaways

- [ ] Any appliance can be physical (dedicated hardware, high performance) or virtual (fast to deploy, scalable, NFV/cloud-friendly).
- [ ] Router = L3, routes packets by IP, separates broadcast domains; switch = L2, forwards frames by MAC (CAM table), separates collision domains; L3 switch does inter-VLAN routing.
- [ ] Firewalls: stateless (per-packet rules) vs. **stateful** (connection state table, auto-allows return traffic) vs. **NGFW** (Layer 7 application awareness/DPI, integrated IPS).
- [ ] **IDS = passive/out-of-band, detect and alert; IPS = inline, detect and block.** Detection is signature-based (known attacks) or anomaly-based (baseline deviations).
- [ ] Load balancer distributes clients across a server pool via a VIP; know round-robin vs. least connections, health checks, and sticky sessions.
- [ ] Forward proxy serves/filters **clients** (outbound); reverse proxy fronts/protects **servers** (inbound, TLS offload, caching).
- [ ] NAS = file-level over the LAN (SMB/NFS); SAN = block-level over a dedicated network (Fibre Channel/iSCSI); clients see shares vs. raw disks.
- [ ] Autonomous APs are standalone; lightweight APs are centrally managed by a **wireless controller** (roaming, RF tuning, policy).
- [ ] CDN caches content at geographically distributed **edge** servers to cut latency and offload the origin.
- [ ] VPN = encrypted tunnel (site-to-site or client-to-site); QoS = classify/mark (DSCP L3, CoS L2) then prioritize; TTL = router hop decrement for loop prevention (ICMP Time Exceeded at 0) and DNS cache lifetime.

## Self-Check Questions

1. A technician must allow servers in a data center to access shared storage that appears to each server as a locally attached disk, using the existing Ethernet network. Which technology and protocol fit best?
2. Security wants malicious traffic stopped automatically before it reaches the LAN, accepting the small risk that legitimate traffic could occasionally be blocked. IDS or IPS, and how must it be deployed?
3. What is the key difference between a forward proxy and a reverse proxy?
4. VoIP calls sound choppy whenever large backups run. Which function fixes this, and what are the two common marking schemes at Layers 3 and 2?
5. A packet arrives at a router with TTL = 1 and must be forwarded another hop. What does the router do?

<details>
<summary>Answers</summary>

1. A **SAN** providing **block-level** storage using **iSCSI** (SCSI over TCP/IP works on existing Ethernet; Fibre Channel would require a dedicated FC fabric).
2. An **IPS**, deployed **inline** in the traffic path so it can drop malicious packets in real time. An IDS only receives a copy of traffic and can merely alert.
3. A **forward proxy** sits in front of **clients** and handles their outbound requests (filtering, caching, anonymity); a **reverse proxy** sits in front of **servers** and handles inbound requests (protecting servers, TLS offload, caching/distribution).
4. **QoS** — classify and prioritize voice traffic using **DSCP** (6-bit field in the IP header, Layer 3) and/or **CoS** (3-bit 802.1p field in the 802.1Q tag, Layer 2), so real-time traffic is queued ahead of bulk data.
5. It decrements TTL to **0**, **discards the packet**, and sends an **ICMP Time Exceeded (Type 11)** message to the source. This prevents endless routing loops and is the mechanism traceroute exploits.
